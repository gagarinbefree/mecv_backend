# MECV backend

[![Tests and build](https://github.com/gagarinbefree/mecv_backend/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/gagarinbefree/mecv_backend/actions/workflows/ci.yml)

Backend цифровой визитки на TypeScript, NestJS, Prisma и Apollo GraphQL.

Работает HTTP GraphQL API с демонстрационным профилем и встроенным Apollo Sandbox. NestJS собирает приложение через функциональные провайдеры без собственных классов. Prisma, миграции и автоматическое заполнение PostgreSQL будут реализованы следующими TDD-этапами; сейчас профиль читается из демонстрационного файла без базы данных. Docker отложен.

Контракт запроса profile и связанных типов описан в [GraphQL-схеме](src/profile/profile.graphql). GraphQL Code Generator создаёт из SDL типы данных и резолверов. HTTP-тесты проверяют вложенные данные, отсутствующий профиль, интроспекцию, HTML Sandbox и обработку ошибок. Скаляру Date разрешены только существующие календарные даты в формате YYYY-MM-DD, годы 0001–9999.

Плашка отражает фактический результат workflow Tests and build в GitHub Actions. Зелёный статус означает, что генерация типов, ESLint, проверка типов, тесты и сборка завершились успешно; отсутствие запусков не является подтверждением успеха.

## Локальный запуск

Нужен Node.js 24.15 или совместимый более новый patch ветки 24. PostgreSQL на текущем этапе не требуется.

~~~shell
npm ci
npm start
~~~

Перед запуском автоматически генерируются типы и выполняется сборка, включая копирование SDL в dist. Открой [Apollo Sandbox](http://127.0.0.1:3000/graphql). Страница загружает редактор с CDN Apollo, поэтому для редактора нужен доступ в интернет; GraphQL API работает локально. Для остановки нажми Ctrl+C.

Пример запроса:

~~~graphql
query {
  profile {
    name
    description
    links { label url }
    skills { name }
    experience { company position startDate endDate achievements }
    projects { name description url }
  }
}
~~~

Данные в [demo-profile.ts](src/profile/demo-profile.ts) явно обозначены как учебные. Транспорт не выбирает способ хранения: [резолверы](src/profile/profile.resolvers.ts) получают асинхронную функцию чтения через провайдер NestJS. Отсутствие профиля возвращает null, а ошибка чтения — стандартный ответ GraphQL без стека реализации. Контекст создаётся заново для каждого запроса.

## Локальная проверка

Нужен Node.js 24.15 или совместимый более новый patch ветки 24.

~~~shell
npm ci
npm run check
~~~

Отдельные команды: npm run lint, npm run typecheck, npm test и npm run build. Каждая автоматически обновляет сгенерированные типы перед запуском. Сборка помещает JavaScript и SDL в dist. HTTP-тесты используют свободные локальные порты и закрывают приложение после каждой проверки.

Dev-зависимости ts-morph и @apollo/gateway нужны для проверки деклараций пакетов NestJS при skipLibCheck: false. Они не включают федерацию или генерацию SDL из классов в приложении.

В .npmrc включена обычная проверка peerDependencies: legacy-peer-deps=false. Глобальная настройка npm не должна позволять создавать lockfile с несовместимыми peer-зависимостями.

## Типы GraphQL

Настройки находятся в [codegen.ts](codegen.ts). Источник типов — SDL; результат записывается в src/generated/graphql.ts, исключён из Git и не редактируется вручную. Для отдельного обновления выполни npm run codegen.

Типы данных и списки неизменяемы. Nullable-поля представлены через null; свойства данных не получают дополнительный undefined. Date явно сопоставлен со string на входе и выходе; [обработчик скаляра](src/graphql/date.scalar.ts) проверяет тип, формат и календарную дату при вводе переменных, литералов и сериализации результата. Новый скаляр без явного сопоставления останавливает генерацию.

Типы функций резолверов включают parent, args, context, info и результат. Сейчас поля схемы не принимают аргументов, поэтому args — Record<PropertyKey, never>. [Контекст запроса](src/graphql/graphql-context.ts) пока представляет неизменяемый словарь unknown без сервисов и загрузчиков; перед использованием неизвестное значение требует проверки. При подключении данных контекст получит конкретные зависимости запроса.

Команда npm test запускает обычные тесты и отдельные проверки типов через TypeScript. Они проверяют даты, nullability, неизменяемость данных и сигнатуры резолверов. npm run test:watch обновляет типы при старте; после изменения SDL перезапусти эту команду.

## Правила разработки

TDD, функциональный стиль без собственных классов, содержательный JSDoc у каждой функции, строгий TypeScript без any. Эти правила распространяются на тесты и проверяются ESLint. Отрицательные тесты отдельно подтверждают запрет классов, any и функций без JSDoc.
